2. INSTALLATION DE DOCKER DESKTOP
═══════════════════════════════════════════════════════════════════════════

── SUR WINDOWS ───────────────────────────────────────────────────────────

  1. Télécharger Docker Desktop :
     https://www.docker.com/products/docker-desktop/

  2. Lancer Docker Desktop Installer.exe
     → Cocher "Use WSL 2 instead of Hyper-V"
     → Suivre les instructions
     → Redémarrer le PC si demandé

  3. Ouvrir Docker Desktop (icône baleine dans la barre des tâches)

  4. Vérifier WSL dans PowerShell :
     wsl --version
     wsl --update

── SUR MACOS ─────────────────────────────────────────────────────────────

  1. Télécharger Docker Desktop :
     https://www.docker.com/products/docker-desktop/

  2. Choisir la version :
     → Apple Silicon (M1/M2/M3/M4) : "Mac with Apple Silicon"
     → Intel                       : "Mac with Intel Chip"

     Pour connaître : menu Apple → À propos de ce Mac

  3. Ouvrir le .dmg et glisser Docker dans Applications

  4. Lancer Docker depuis Applications (mot de passe demandé)

3. CLONER SUPABASE
═══════════════════════════════════════════════════════════════════════════

── POWERSHELL (Windows) ──────────────────────────────────────────────────

  # Aller dans le dossier utilisateur
  cd "C:\Users\Sahnoun HAWALA"

  # Cloner le dépôt Supabase
  git clone --depth 1 https://github.com/supabase/supabase

  # Créer le dossier de travail
  mkdir supabase-project

  # Copier les fichiers Docker
  Copy-Item -Path "supabase\docker\*" -Destination "supabase-project" -Recurse -Force

  # Copier le fichier .env
  Copy-Item -Path "supabase\docker\.env.example" -Destination "supabase-project\.env" -Force

  # Se déplacer dans le dossier
  cd supabase-project

── GIT BASH (optionnel) ──────────────────────────────────────────────────

  cd /c/Users/"Sahnoun HAWALA"
  git clone --depth 1 https://github.com/supabase/supabase
  mkdir supabase-project
  cp -rf supabase/docker/* supabase-project
  cp supabase/docker/.env.example supabase-project/.env
  cd supabase-project

6. MIGRATIONS DE LA BASE DE DONNÉES
═══════════════════════════════════════════════════════════════════════════

── CONCATÉNER TOUTES LES MIGRATIONS ─────────────────────────────────────

  cd "C:\Projects\accounting-ai-automation\infra\supabase\migrations"

  $output = "C:\Users\Sahnoun HAWALA\all_migrations.sql"

  Get-ChildItem -Filter "*.sql" | Sort-Object Name | ForEach-Object {
    "`n-- ═══════════════════════════════════════════════════════════════"
    "--  Fichier : $($_.Name)"
    "-- ═══════════════════════════════════════════════════════════════`n"
    Get-Content $_.FullName -Raw
  } | Out-File -FilePath $output -Encoding utf8

── EXÉCUTER LES MIGRATIONS ──────────────────────────────────────────────

  cd "C:\Users\Sahnoun HAWALA\supabase-project"

  # Copier dans le conteneur
  docker cp "C:\Users\Sahnoun HAWALA\all_migrations.sql" supabase-db:/tmp/all_migrations.sql

  # Exécuter
  docker compose exec db psql -U postgres -d postgres -f /tmp/all_migrations.sql

── SI ERREUR D'ORDRE (rls.sql avant profiles.sql) ───────────────────────

  # Créer manuellement super_admins si manquante
  docker compose exec db psql -U postgres -d postgres -c @"
  CREATE TABLE IF NOT EXISTS public.super_admins (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email TEXT NOT NULL UNIQUE,
    created_at TIMESTAMPTZ DEFAULT NOW()
  );
  CREATE INDEX IF NOT EXISTS idx_super_admins_email ON public.super_admins(email);
  ALTER TABLE public.super_admins ENABLE ROW LEVEL SECURITY;
  "@

  # Ajouter le super-admin
  docker compose exec db psql -U postgres -d postgres -c @"
  INSERT INTO public.super_admins (email)
  VALUES ('haouala18@gmail.com')
  ON CONFLICT (email) DO NOTHING;

  UPDATE public.profiles
  SET role = 'super_admin'
  WHERE email = 'haouala18@gmail.com';
  "@

  # Re-exécuter rls.sql
  docker cp "C:\Projects\accounting-ai-automation\infra\supabase\migrations\20261005000006_rls.sql" supabase-db:/tmp/rls.sql
  docker compose exec db psql -U postgres -d postgres -f /tmp/rls.sql

9. COMMANDES UTILES DU QUOTIDIEN
═══════════════════════════════════════════════════════════════════════════

── DÉMARRAGE QUOTIDIEN ──────────────────────────────────────────────────

  # 1. Lancer Docker Desktop (icône baleine)
  # 2. Attendre qu'il soit prêt
  # 3. Dans PowerShell :

  cd "C:\Users\Sahnoun HAWALA\supabase-project"
  docker compose up -d

── ÉTAT DES SERVICES ────────────────────────────────────────────────────

  docker compose ps

── LOGS EN TEMPS RÉEL ───────────────────────────────────────────────────

  # Tous les services
  docker compose logs -f

  # Un service précis
  docker compose logs -f supabase-db
  docker compose logs -f supabase-auth
  docker compose logs -f supabase-storage

── ARRÊTER / REDÉMARRER ────────────────────────────────────────────────

  # Arrêter (garde les données)
  docker compose stop

  # Redémarrer
  docker compose start

  # Redémarrer un service
  docker compose restart supabase-db

  # Arrêter + supprimer les conteneurs (garde les volumes)
  docker compose down

── ACCÈS À LA BASE ─────────────────────────────────────────────────────

  # Prompt psql interactif
  docker compose exec db psql -U postgres -d postgres

  # Commandes psql utiles :
    \dt public.*     → Lister les tables
    \d table_name    → Décrire une table
    \du              → Lister les utilisateurs
    \l               → Lister les databases
    \q               → Quitter

── ACCÈS DIRECT POSTGRESQL ─────────────────────────────────────────────

  Depuis un client PostgreSQL (DBeaver, pgAdmin, TablePlus) :

    Host     : localhost
    Port     : 5432
    Database : postgres
    User     : postgres
    Password : (POSTGRES_PASSWORD du .env)

11. DÉPANNAGE
═══════════════════════════════════════════════════════════════════════════

── ERREUR : "no configuration file provided" ────────────────────────────

  Cause : Tu n'es pas dans le dossier supabase-project
  Solution :
    cd "C:\Users\Sahnoun HAWALA\supabase-project"

── ERREUR : "port already in use" ───────────────────────────────────────

  Cause : Un autre service utilise le port (3000, 8000, 5432, 6543)
  Solution :
    # Voir ce qui utilise le port 8000
    netstat -ano | findstr :8000

    # Tuer le processus (remplace PID par le numéro)
    taskkill /PID <PID> /F

── ERREUR : "Docker daemon is not running" ──────────────────────────────

  Cause : Docker Desktop n'est pas lancé
  Solution : Lancer Docker Desktop depuis le menu Démarrer

── ERREUR : Conteneurs "unhealthy" ──────────────────────────────────────

  Cause : Problème dans un service
  Solution :
    docker compose logs supabase-db
    docker compose logs supabase-auth

── ERREUR : "Unexpected token 'U'" sur le login ─────────────────────────

  Cause : /api/audit/log retourne du texte brut au lieu de JSON
  Solution : Vérifier que la route utilise NextResponse.json()

── ERREUR : "relation public.X does not exist" ──────────────────────────

  Cause : Migrations exécutées dans le mauvais ordre
  Solution : Exécuter les migrations manquantes une par une

── RESET COMPLET (⚠️ SUPPRIME TOUT) ────────────────────────────────────

  cd "C:\Users\Sahnoun HAWALA\supabase-project"
  docker compose down -v

  # Puis recommencer depuis l'étape 5

13. NOTES IMPORTANTES
═══════════════════════════════════════════════════════════════════════════

⚠️  SÉCURITÉ
  • Ne JAMAIS committer le fichier .env
  • Ne JAMAIS partager les clés (ANON_KEY, SERVICE_ROLE_KEY, POSTGRES_PASSWORD)
  • Ne JAMAIS exposer ton instance sur Internet sans reverse proxy + HTTPS

⚠️  DOCKER DESKTOP
  • Doit rester allumé pour que Supabase fonctionne
  • Après chaque redémarrage du PC : relancer Docker Desktop puis
    "docker compose up -d"

⚠️  PERSISTANCE
  • Les données sont dans supabase-project\volumes\
  • Sauvegarder régulièrement ce dossier
  • La DB est dans volumes\db\data (ne pas éditer à la main)

⚠️  PERFORMANCE
  • Docker Desktop → Settings → Resources
  • Allouer au minimum : 4 GB RAM, 2 CPU
  • Recommandé : 8 GB RAM, 4 CPU

⚠️  MISES À JOUR
  • Pour mettre à jour Supabase :
    docker compose pull
    docker compose up -d

⚠️  LIMITES DE L'AUTO-HÉBERGEMENT
  • Pas de branches (comme en Cloud)
  • Pas de PITR (Point-in-Time Recovery)
  • Pas de métriques avancées
  • Pas de management API
  • Tu es responsable des sauvegardes et mises à jour

⚠️  FICHIERS IMPORTANTS
  • .env                        → Clés et configuration
  • docker-compose.yml          → Configuration des services
  • volumes/db/data             → Données PostgreSQL
  • volumes/storage             → Fichiers uploadés (PDF, images)

⚠️  URLS PAR DÉFAUT
  • Studio          http://localhost:8000
  • API REST        http://localhost:8000/rest/v1/
  • API Auth        http://localhost:8000/auth/v1/
  • API Storage     http://localhost:8000/storage/v1/
  • PostgreSQL      localhost:5432
  • Pooler          localhost:6543
