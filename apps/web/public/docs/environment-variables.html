🎛️ Variables d'environnement

Guide de configuration Vercel — Accounting AI Automation

ℹ️ Important — Ces variables ne se configurent pas dans la page Settings. Elles doivent être ajoutées dans le dashboard Vercel, onglet Settings → Environment Variables. Sans elles, certaines fonctionnalités (base de données, IA, emails) ne fonctionneront pas.
🔗 Ouvrir les Environment Variables Vercel

📋 Variables obligatoires

NEXT_PUBLIC_SUPABASE_URL

🗄️ URL de votre projet Supabase (connexion à la base de données).

  1. Connectez-vous sur supabase.com/dashboard
  2. Sélectionnez votre projet
  3. Allez dans Settings → API
  4. Copiez la valeur Project URL (format : https://xxxxx.supabase.co)
  5. Sur Vercel → ajoutez la variable avec cette valeur
Production Preview Development

NEXT_PUBLIC_SUPABASE_ANON_KEY

🔑 Clé publique Supabase (utilisée côté client pour l'authentification).

  1. Sur supabase.com/dashboard → votre projet
  2. Settings → API
  3. Copiez la valeur anon public (commence par eyJ...)
  4. Sur Vercel → ajoutez la variable
Production Preview Development
💡 Cette clé est publique (exposée au navigateur) — c'est normal, elle est protégée par les RLS Supabase.

SUPABASE_SERVICE_ROLE_KEY

🛡️ Clé administrateur Supabase (accès total, bypass RLS). Utilisée uniquement côté serveur (cron, webhook).

  1. Sur supabase.com/dashboard → votre projet
  2. Settings → API
  3. Sous Project API keys, cliquez sur Reveal à côté de service_role
  4. Copiez la clé (commence par eyJ...)
  5. Sur Vercel → ajoutez la variable
Production uniquement
⚠️ Cette clé donne un accès total à votre base. Ne la partagez jamais et ne la mettez jamais dans du code client.

GROQ_API_KEY

🤖 Clé API Groq pour l'extraction et le résumé IA des documents.

  1. Créez un compte sur console.groq.com
  2. Allez dans API Keys → Create API Key
  3. Copiez la clé (commence par gsk_...)
  4. Sur Vercel → ajoutez la variable
Production Preview
💡 Le plan gratuit Groq est suffisant pour tester.

RESEND_API_KEY

📧 Clé API Resend pour l'envoi d'emails (rapports, tests).

  1. Créez un compte sur resend.com
  2. Allez dans API Keys → Create API Key
  3. Donnez un nom (ex: accounting-ai-prod), choisissez Full access
  4. Copiez la clé (commence par re_...)
  5. Sur Vercel → ajoutez la variable
Production
💡 Vous pouvez également saisir cette clé directement dans la page Settings (champ "Clé API Resend") — elle sera alors stockée dans Supabase.

CRON_SECRET

⏰ Secret utilisé par Vercel Cron pour authentifier les appels automatiques à /api/cron/*.

  1. Générez une chaîne aléatoire sécurisée (ex: via generate-secret.vercel.app)
  2. Sur Vercel → ajoutez la variable avec cette valeur
  3. Vercel l'enverra automatiquement dans le header Authorization: Bearer <valeur>
Production Preview
⚠️ Ne communiquez cette valeur à personne.

📋 Variables optionnelles

NEXT_PUBLIC_APP_URL

🌐 URL publique de votre application (liens dans les emails, redirections OAuth).

  1. Récupérez l'URL de votre déploiement Vercel (ex: https://accounting-ai-automation.vercel.app)
  2. Sur Vercel → ajoutez la variable
Production Preview Development
💡 Development : http://localhost:3000

VERCEL_AUTOMATION_BYPASS_SECRET

🔓 Bypass de la protection Vercel Authentication pour les tests automatisés (CI, Playwright).

  1. Sur Vercel → Settings → Deployment Protection
  2. Activez Protection Bypass for Automation
  3. Copiez le secret généré
  4. Ajoutez-le comme variable d'environnement
Preview uniquement
💡 Si vous ne faites pas de tests automatisés, cette variable est inutile.

🚀 Procédure générale d'ajout sur Vercel

  1. Connectez-vous sur vercel.com/dashboard
  2. Sélectionnez votre projet accounting-ai-automation
  3. Allez dans l'onglet Settings
  4. Dans le menu de gauche, cliquez sur Environment Variables
  5. Cliquez sur Add New
  6. Remplissez :
    • Key : le nom exact de la variable
    • Value : la valeur copiée
    • Environments : cochez Production / Preview / Development
  7. Cliquez sur Save
  8. Redéployez votre application (Deployments → ⋯ → Redeploy)

⚠️ Bonnes pratiques

  • 🔒 Ne partagez jamais les valeurs de SUPABASE_SERVICE_ROLE_KEY, GROQ_API_KEY, RESEND_API_KEY et CRON_SECRET
  • 🔄 Après ajout/modification d'une variable, vous devez redéployer
  • 🧪 Testez en Preview avant de passer en Production
  • 📝 Conservez une copie des valeurs dans un gestionnaire de mots de passe
  • ❌ N'ajoutez jamais ces variables dans un fichier .env commité sur Git
